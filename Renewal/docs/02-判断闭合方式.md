# 02 判断闭合方式

> 目的：搞清楚参数被什么符号包裹，才能正确地「逃逸」出去。闭错了，payload 只会报语法错误。

## 2.1 常见的闭合方式

| 闭合形式 | 说明 | 典型 payload 片段 |
| --- | --- | --- |
| `' '` | 单引号包裹 | `'` |
| `" "` | 双引号包裹 | `"` |
| `( )` | 括号包裹数字 | `)` |
| `(( ))` | 双层括号 | `))` |
| `(' ')` | 括号 + 单引号 | `')` |
| `((''))` | 双层括号 + 单引号 | `'))` |
| `(" ")` | 括号 + 双引号 | `")` |
| `((" "))` | 双层括号 + 双引号 | `"))` |
| 无闭合 | 数字型，直接当数值用 | 不需要引号 |

注意：闭合 **不是一个符号，而是一段「前半截」**。原句是 `where id='$id'`，你输入的内容会插在第一个 `'` 之后，所以你要补的其实是「让后面的部分继续合法」的那一截。

## 2.2 转义字符 `\`

MySQL 里 `\` 是转义符，作用是：**把它后面紧跟的那一个字符当作普通字符串内容**，不当作语法符号。

利用这个特性可以反推闭合：

```
输入：'2\' LIMIT 0,1'
```

页面报错。把错误信息按「去头去尾」处理，只看中间有效部分：

```
'2\' LIMIT 0,1
```

意思是：你输入的 `'` 确实进到了语句里，并且和后面的内容发生了冲突 —— 说明参数是被引号包裹的。

## 2.3 注释符

闭合之后，原语句剩下的部分必须被「截断」掉，否则语法不成立。用于截断的注释符：

| 注释符 | 说明 |
| --- | --- |
| `-- ` | SQL 标准注释，**后面必须跟一个空格** |
| `--+` | `+` 在 URL 里等于空格，所以 `--+` 等价于 `-- `，GET 请求里最常用 |
| `#` | MySQL 专用注释，到行尾为止 |
| `/**/` | 块注释，可插在语句中间，也常用来绕过简单过滤（如 `union/**/select`） |

> `+` 在 **GET 请求**的查询字符串里会被解码成空格。所以 `'` 后面跟 `--+`，实际执行的注释是 `-- `。

## 2.4 验证：`2'--+`

原语句：

```sql
select username, password from tablex where id='2'--+' limit 0,1;
```

经过注释截断后，实际执行的是：

```sql
select username, password from tablex where id='2'
```

因为 `--+` 之后的内容全部被忽略，语句依然合法。

所以判断逻辑很直接：

| 输入 | 现象 | 结论 |
| --- | --- | --- |
| `2'` | 报错 / 异常 | 参数被引号包裹，且没有过滤 |
| `2'--+` | **查询正常** | 确实是 `' '` 闭合，注释符生效 |
| `2` | 正常 | 数字型或未触发 |

用户实测：输入 `2'--+` 查询正常 → **确定是单引号闭合**。

## 2.5 判断顺序建议

1. 先打 `'`，观察是否报错；
2. 再打 `'--+`，观察是否恢复正常；
3. 若都不行，依次试 `"`、`)`、`'))`、`")`；
4. 数字型（无闭合）就直接 `and 1=1` / `and 1=2` 看差异；
5. 每一步都要记录「输入 → 现象」，别凭感觉。

## 2.6 常见坑

- `--` 后面**没空格**不生效，必须写成 `-- ` 或 `--+`。
- POST 请求里 `+` 不会被解码成空格，要用 `-- `（空格）或 `#`。
- 有的框架会 `addslashes`，单引号被转义成 `\'`，此时可以考虑宽字节、二次编码等方向。
- 页面「一切正常」也可能是被 WAF 拦了并返回了假页面，要看响应体和状态码，别只看标题。
