# 07 环境组合与防御

## 7.1 常见技术栈组合

渗透时先看**指纹**，再判断能用到哪种注入方式（不同数据库的函数、系统表不一样）。

| 组合 | 缩写 | 数据库 | 特点 |
| --- | --- | --- | --- |
| Windows + IIS + ASP/ASPX + Access/MSSQL | — | Access / MSSQL | 老站多；Access 没有 `information_schema` |
| Windows + Apache + PHP + MySQL | **WAMP** | MySQL | 常用集成环境（phpStudy、XAMPP、宝塔） |
| Linux + Apache/Nginx + PHP + MySQL | **LAMP / LNMP** | MySQL | 最常见；宝塔面板一键搭建，默认配置问题多 |
| Linux + Tomcat + Java(JSP) + Oracle/MySQL | — | Oracle / MySQL | 常带 root 权限，危害大 |
| Linux + Nginx + Python(Django/Flask/Tornado/FastAPI)/Go(Beego/Gin) + MySQL | — | MySQL | 新项目多，ORM 用错照样注入 |

> 快速识别：看 `Server` 响应头、URL 后缀（`.php`/`.jsp`/`.aspx`）、报错页面风格、Cookie 名（`PHPSESSID`→PHP，`JSESSIONID`→Java）。

不同数据库的差异：

| 数据库 | 系统表 / 查库方式 | 注释符 |
| --- | --- | --- |
| MySQL | `information_schema.tables/columns` | `-- `、`#`、`/**/` |
| MSSQL | `sysobjects`、`syscolumns` | `--`、`/* */` |
| Oracle | `all_tables`、`user_tables` | `--` |
| Access | 无系统表，只能猜表名 | 无 |
| PostgreSQL | `pg_catalog`、`information_schema` | `--`、`/* */` |

## 7.2 防御：从代码层修

### 1) 参数化查询（首选）

```php
// 错误：字符串拼接
$sql = "select * from users where id='$id'";

// 正确：占位符 + 绑定
$stmt = $pdo->prepare('select * from users where id = ?');
$stmt->execute([$id]);
```

```java
// Java
PreparedStatement ps = conn.prepareStatement("select * from users where id = ?");
ps.setString(1, id);
```

```python
# Python
cur.execute("select * from users where id = %s", (id,))
```

**参数化查询让输入永远是「值」，不可能变成「语法」**，这是唯一能根治的写法。

### 2) 类型强转与白名单

```php
$id = (int)$_GET['id'];                 // 强转
$order = in_array($col, ['id','name'], true) ? $col : 'id';  // 排序字段用白名单
```

`order by`、表名、列名**不能用占位符**，必须用白名单映射。很多注入就藏在这些「不能参数化」的地方。

### 3) 数据库权限最小化

- Web 应用不要用 `root` 连数据库；
- 只给 `select/insert/update/delete`，不给 `file`、`drop`、`grant`；
- 不同业务用不同账号，别共用一个高权限库管。

### 4) 错误信息不回显

```php
ini_set('display_errors', '0');
error_log($e->getMessage());   // 只记日志，别打给用户
```

报错注入（`E`）之所以有效，就是因为数据库错误被原样吐到了页面上。

### 5) 输入校验 + WAF + 日志

- 长度、字符集、格式校验（比如 id 必须是纯数字）；
- WAF 拦已知 payload（能挡脚本小子，挡不住人工）；
- **记录并监控**异常的 `select`、`union`、`sleep` 关键字请求。

## 7.3 防御检查清单

- [ ] 所有 SQL 都走参数化查询，没有一处字符串拼接
- [ ] `order by` / 表名 / 列名使用白名单，不直接取用户输入
- [ ] 数据库账号为最小权限，应用账号不能用 `root`
- [ ] 生产环境关闭 `display_errors`，错误不返回给前端
- [ ] 关键接口有频率限制和异常日志告警
- [ ] 定期用 sqlmap 对**自有系统**做回归测试（授权范围内）

## 7.4 一句话总结

> 注入的本质是「数据被当成了代码」。
> 参数化查询解决的是**语法边界**问题，白名单解决的是**标识符**问题，最小权限解决的是**后果**问题。三者缺一不可。
